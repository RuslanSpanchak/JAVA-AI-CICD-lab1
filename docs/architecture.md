# Архітектура AI-агента

## 1. Призначення

Агент `build-engineer` автоматизує передбачуваний цикл невеликого Java-проєкту: аналіз структури, створення/перевірка коду і тестів, налаштування Maven, формування GitHub Actions workflow та перевірка результату.

## 2. Manifest агента

`.github/agents/build-engineer.agent.md` задає ім'я, роль, інструменти, контекст проєкту, правила безпеки, порядок роботи й критерії завершення. Це постійний опис поведінки спеціалізованого агента, а не скрипт складання.

## 3. Skills

| Skill | Вхідні дані | Результат | Перевірка |
|---|---|---|---|
| `project-scaffold` | вимоги, структура каталогу | Java-код і JUnit-тести | перевірка API, крайніх випадків і структури Maven |
| `build-and-test` | `pom.xml`, код, тести | конфігурація Maven і результат тестів | `mvn -B clean verify` та звіт Surefire |
| `github-actions` | Maven-проєкт і вимоги CI | `.github/workflows/ci.yml` | перевірка matrix, JDK, команди Maven і дозволів |

Кожен skill містить умови застосування, вхідні дані, результат, перевірку та поведінку при помилці.

## 4. Commands / prompt files

Файли `.github/prompts/*.prompt.md` є іменованими prompt-командами для GitHub Copilot у сумісному редакторі. Вони відокремлюють типові операції: Git init, створення застосунку, налаштування build, CI та перевірку. Виклик промпта запускає інструкцію AI; він сам по собі не є shell-командою.

## 5. Orchestrator

`.github/prompts/init.prompt.md` — оркестратор. Він виконує етапи у фіксованому порядку:

1. передумови та огляд існуючих змін;
2. створення/перевірка коду і тестів;
3. налаштування Maven та локальний `clean verify`;
4. формування GitHub Actions після успішної локальної перевірки;
5. фінальна перевірка й звіт.

Якщо етап не проходить, оркестратор має зупинитися, описати фактичну помилку та не оголошувати успіх. Оскільки оркестрація реалізована інструкцією для AI, її виконання залежить від можливостей обраного Copilot-клієнта; це не окремий детермінований workflow engine.

## 6. Відповідність рекомендованій структурі

- `.github/agents/build-engineer.agent.md` — manifest агента.
- `.github/prompts/*.prompt.md` — команди і prompt-оркестратор.
- `.github/skills/*/SKILL.md` — повторно використовувані skills.
- `.github/workflows/ci.yml` — CI/CD на GitHub Actions.
- `src/main/java` — стандартний Maven-каталог коду застосунку.
- `src/test/java` — стандартний Maven-каталог тестів замість окремого `tests/`, відповідно до конвенції Maven.
- `pom.xml` — опис Java-версії, JUnit-залежності та Maven-плагінів; `CMakeLists.txt` не використовується, бо потрібний build tool — Maven, а не CMake.
- `docs/architecture.md` і `docs/usage.md` — архітектура, мапування файлів і порядок використання.

## 7. Обмеження AI і захист

Агент не повинен просити секрети, приховувати помилки, пропускати тести, автоматично публікувати зміни, переписувати Git-історію чи видаляти файли. Локальна перевірка не є доказом того, що CI пройшов на Linux, Windows і macOS; це потрібно підтвердити історією запусків GitHub Actions.

## 8. Цільовий AI-клієнт

Структура орієнтована на GitHub Copilot у редакторі, що підтримує agent profiles, prompt files та skills. Якщо викладач визначив інший AI-інструмент, потрібно адаптувати розташування/розширення файлів до цього клієнта, зберігши ті самі ролі manifest, skills, commands і orchestrator, а зміни відобразити тут.
